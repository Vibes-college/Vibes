# 按任务范围执行Agent指导规则

## 用户与核心路径

- US1（P1）：维护者明确授权一项工作后，Agent在已确认范围内连续完成实现、必要验证、文档与交付；只有真正缺少决定、权限或外部条件时才等待。独立验收：已有授权不因生成spec、plan或辅助清单重复询问；需要本人决定的门槛仍保留。
- US2（P1）：维护者使用项目Skills时，实际加载的规则与项目约定一致；无需的研究、产物和重复任务不会被默认制造。独立验收：项目预设解析与Skills生成结果可复核，重复执行不丢失适配。
- US3（P2）：维护者沿索引查找规则，Agent只读取相关材料，合并后按最终实现核对受影响文档。独立验收：历史规格、必要检查和有效验收证据保留，模板不反复复制交付流程。

## 功能要求与验收

- FR-001：plan只研究影响实现的未决技术问题；research及data-model/contracts/quickstart按项目必要性规则生成，不作为无条件前置条件，不逐依赖调查通用最佳实践。
- FR-002：明确授权持续有效；不再无条件要求计划确认或workflow的spec/plan双审批。用户要求阶段审阅时保留该门槛，未决范围/成本/权限问题仍询问，不将超时当同意。
- FR-003：未勾选清单仅在适用当前阶段、实际阻塞工作或明确指定人工审阅时暂停依赖步骤；辅助清单不自动成为门槛，Agent不代替审阅者勾选。
- FR-004：执行失败后区分依赖暂停与任务结束；Agent修复本任务导致的问题并重跑受影响检查，必要交付检查不减少。
- FR-005：入口按任务路由到宪章、功能索引和交付文档；已读取且未变化的材料不重复读取，小任务不要求先读固定文档栈。
- FR-006：独立澄清问题可每轮合并最多三个，依赖问题逐个问；以含义清楚为准，不限制回答词数，不重复已确认事项。
- FR-007：converge按需求引用与实际行为检查已有任务，仅追加尚未记录的缺口；已有未完成任务仍须完成，零新增任务不代表实现完成。
- FR-008：合并后依据PR最终差异和合并后的代码核对所有受影响说明；需要追溯原因时再读具体commit，保留文档语义核对和收尾记录。
- FR-009：checklist描述精确限定为需求质量审查，不误触发功能测试或发布验收任务。
- FR-010：spec/plan/tasks模板引用唯一交付流程，相关经验措施只记录一次；不要求多个文件反复写无相关经验。
- FR-011：公共hook规则按需读取；未配置扩展时静默跳过，不在每个Skill内重复长篇流程。配置存在时仍遵守声明的执行条件和授权边界。
- FR-012：使用可维护的项目预设与workflow覆盖层，保留上游来源及生成方式；保持已安装命令名称，实际生成的Skills与源文件一致。
- FR-013：纯文档、Agent规则、Skills和Spec Kit流程配置的PR仅运行轻量文档检查，不启动网站构建、浏览器测试或部署；Draft同样按影响选择。混入网页、脚本、依赖或GitHub CI执行配置时保守回退，不跳过必要的保护状态。
- SC-001：上述11项审查发现逐项对应修正文件与验证证据；已授权与需要审批两类workflow路径均可复核。
- SC-002：按项目要求完成检查及独立审查，修复阻塞项；文档准确说明使用、更新与恢复项目适配的方法。

## 明确不做

不改变Explore页面、Paseo功能、网站变更所需的构建/发布门槛、现有测试覆盖或数据；仅为识别Agent规则补充CI范围分类及Draft检查分流。不安装npm依赖，不自动合并PR，不修改已冻结规格正文，不更改全局Skills或个人记忆。

## 端差异

规则用于本仓库Agent、项目Skills及Spec Kit CLI工作流；网页访客行为无变化。CLI覆盖必须通过解析验证，不能只靠自然语言声称固定gate已取消。无需为本需求制作网页预览。

## 研究与交付

research记录原生预设与workflow覆盖机制；不生成数据模型、接口合同或quickstart。任务与证据见同目录tasks，交付遵循docs/system/checks-and-release.md。相关经验在plan记录一次。
