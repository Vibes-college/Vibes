# 文档时态与冻结治理

## 需求与验收

用户需要打开文档就能判断它描述现状还是历史，且索引能清楚定位相关资料，不限制正常排查次数。以确定性校验与人工审阅共同控制文档质量；网站功能实施不在范围内。

- FR-001：宪章定义living/frozen/scratch、PR合并冻结点、最终行为同步与修订追溯。
- FR-002：AGENTS四条导航，两个索引与目录/状态/影响功能双向一致。
- FR-003：治理Markdown标签与白名单机器检查，产品文章/固定上游资产明确区分。
- FR-004：已冻结正文不可修改/删除/改名，允许状态前进、追加amended-by及首次据实补记可选日期；不许回退状态规避。LESSONS条目仅追加。
- FR-005：裁剪项目模板；默认spec/plan/tasks，research记录技术未知或重要取舍，额外产物由Agent在spec列明必要性与用途。
- FR-006：规格无总行数上限；功能120行、宪章100行、AGENTS150行、代码300行仅作审阅提示，不使CI失败；周报报告文档和代码行数，比例仅供观察，不触发告警或裁剪。
- FR-007：docs:check进入check/verify/CI，错误有解释，失败场景有自动测试；最终文档与实现同PR生效。

- FR-008：自动化E2E统一Playwright，保留触摸横滑与320px覆盖；CI按影响分流，未知范围完整验证，分类失败不能使必需检查假绿。
- FR-009：小任务简化流程，主动提出实际问题；不以自然语言禁词、固定任务顺序、读取次数或逐文件批准替代判断；开发阶段允许逐步补齐交付文件，不强制占位文档。

## 明确不做与端差异

不开发多语言/搜索，不增加依赖，不改文章和上游资产，不部署/合并，不另建CLAUDE入口或decisions目录。CLI本地使用origin/main，CI使用事件提交基线；两端缺基线均失败。

## 验收标准

合法样例与实际仓库通过；缺标签/越白名单/漏索引/非法关系/冻结篡改与删除/未完成合并任务/缺基线失败。完整verify与budget通过；不从文档检查外推网站线上状态。

## 行数与批准

不按目录/单文件行数阻断CI；代码300行仅提醒职责审阅。使用既有Node测试，无额外批准产物或未决技术选型。
