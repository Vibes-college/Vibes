# Paseo原生助手分层加载技术计划

## 技术决定与职责

### 底座、源码与构建

固定官方v0.7.2 / `9400a49af670fdb5db4af58e73f8df98588dbea9`，复用已从main建立的codex/012-paseo-webui-loading分支及PR #11实施；不引用011未合并代码，不以旧20.86 MB构建作新版基线。官方使用Expo54、Router6、React19.1及Metro，Vibes使用Astro/Vite与React19.2；两个构建保持独立，不把官方依赖塞进Vibes的React依赖图，也不先改造上游为Vite。

自有文件以下均为拟建路径，按对应任务需要才创建。`third_party/paseo-webui/upstream.json`保存仓库、提交、锁文件摘要、许可和构建输入；`third_party/paseo-webui/patches/`保存有序补丁及新增overlay文件。优先利用官方`PASEO_WEB_PLATFORM`解析覆盖，保留`.web`默认回退，不在产物上手工删代码。完整源码与中间构建位于`.scratch/paseo-webui/`，不提交整个上游仓库；保留上游Apache-2.0及依赖许可，构建来源说明写入`docs/system/local-assistant.md`。

`scripts/paseo-webui-build.ts`按固定提交和已审阅锁文件重建：先校验来源、再严格应用补丁、执行官方`build:web`，生成资源清单和哈希，最后接入`scripts/build.ts`。CI只发布选定配置。失败、补丁不匹配、资源缺失、未知配置均中止，不能回退到旧产物或继续发布。官方安装含postinstall/prepare，应先列明锁文件依赖与脚本必要性并取得新增依赖授权；安装盘点及待授权命令见research的R7；获许可后执行。自有编排尽量用现有Node工具与测试，不新增压测框架。

### 接入前置关卡G1

基于已保存的固定B0与同版真实Luna、工具、审批和一次刷新证据，先进行G1直接挂载、导航、尺寸和键盘探针。T003其余项与T004不再整体串行阻塞T005；仍按实际证据完成，不能提前勾选。

用户已说明iframe的键盘、尺寸和手感问题，直接挂载为优先方向。只有直接挂载遇到具体阻碍且确有必要时才评估iframe，不因实现方便而改成iframe优先。探针使用新建Default permissions受控会话并核对权限；已有自动审查会话切回默认权限及停止子进程的已知问题仍保留，交付前修复或明确支持边界，不新增默认自动授权。

官方`index.ts`没有可复用的`mountPaseoApp`。先验证受控模块入口：保留polyfill、Unistyles、官方根providers与HostRuntime，仅增加宿主挂载/展示边界，隔离Expo Router对外层URL/history的控制；Paseo独立React root不得接收Vibes React元素或共享hooks实例。

探针在真实生产资源前缀和Astro导航下验证：首次初始化一次、关闭重开不重建、文章间导航不改错URL/返回栈、焦点与滚动正确、动态资源可加载、核心同步仍工作。若实现需要大幅改写路由/providers或无法隔离全局CSS，则切换到同源独立文档容器探针，保留官方路由。独立文档需额外验证Astro换页是否重载iframe、隐藏是否真正传递、CSP及上下文桥；同源iframe是路由/CSS边界，不声称安全隔离。

G1选定一种接入方式后固定给两个候选，不同时维护两种宿主实现。两种方式都无法保留官方核心并满足路径要求时，输出具体失败证据与补丁代价，停止扩展功能；不能悄悄退回assistant-ui或定制恢复状态机。

### 宿主接口与唯一所有权

`src/components/LocalAssistant.astro`提供轻量入口及持久容器；`src/scripts/paseo-boot.ts`只响应首次主动打开；`src/features/paseo-webui/host.ts`管理加载状态、展示、错误重试与关闭焦点。拟定挂载契约置于`src/features/paseo-webui/contract.ts`，这里定义边界，不额外生成contracts文档：

| 方向          | 数据/操作                                                           | 限制                                                              |
| ------------- | ------------------------------------------------------------------- | ----------------------------------------------------------------- |
| 宿主→助手     | mount、presentation（可见/焦点/页面前台）、locale、公开作品资料草稿 | 重复mount幂等；作品ID/标题/规范链接/原作链接/简述有界；不自动发送 |
| 助手→宿主     | 首次可操作、加载/致命错误、请求收起、公开展示状态                   | 不传配对秘密、聊天正文、工具执行权限或原始异常                    |
| 用户→原生助手 | 配对、发送、审批、停止、断开、忘记                                  | 全由官方运行机制执行；宿主不另建客户端或代发权限请求              |
| 显式退出→助手 | dispose                                                             | 仅在真正退出/卸载时清理；收起和普通导航不调用                     |

独立文档若启用消息桥，限定source/origin、会话握手、消息类型、字段和长度，不接受任意RPC；配对在助手内完成，不经URL传递。模块模式也采用相同数据约束。宿主展示状态与上游document/AppState合成，而不是用CSS隐藏冒充后台；不能为省CPU停止权威状态合并或漏掉待审批。

保留`HostRuntime`全局单例、`HostSessionManager`、`ManagedDaemonSession/SessionProvider`、directory/timeline副本、缓存、client activity与恢复代次隔离。精简仅作用于功能依赖及呈现层。缓存/凭据按实际官方行为审阅后说明；忘记设备按host删除凭据与恢复数据，异步完成需核对，不能误删另一host，也不承诺清空未调查的所有草稿/布局。

### 首次打开与外围分层

助手生命周期：未打开→加载中→原生初始化/核对→可操作；资源失败→可重试。并发点击合并一次初始化，关闭不把进行中的初始化重复启动，离线首次打开有可见错误；失败重试不能新建第二套runtime。普通Explore不得预取助手入口、字体、样式、图标、连接或缓存初始化。打开后资源缓存可复用，整页刷新仍等待用户打开才初始化；浏览器原生磁盘缓存不等于主动预加载。

| 能力                                    | A：完整按需加载                              | B：构建精简                                       | 共同保证                                               |
| --------------------------------------- | -------------------------------------------- | ------------------------------------------------- | ------------------------------------------------------ |
| 原生聊天、会话、工具、审批、配对、恢复  | 核心加载                                     | 相同核心                                          | 不更换状态语义                                         |
| 基础Markdown、文本代码块、工具参数/结果 | 保留                                         | 保留                                              | 复制保留原文，长内容有明确查看路径                     |
| Mermaid                                 | 用户展开后加载引擎                           | 普通代码块与复制源码                              | 不把内嵌runtime提前留在主包，不削弱隔离策略            |
| 终端与文件编辑器                        | 首次打开面板加载                             | 无编辑/交互终端入口；文件路径给文本查看或明确说明 | Agent shell/读写文件/审批仍可用                        |
| 复杂diff与语法高亮                      | 显式展开/稳定内容时按需                      | 文本diff与无高亮代码                              | 不丢修改内容；共享高亮依赖需单独审计                   |
| 九语言                                  | 选中语言与英文回退先加载，其余切换时加载     | 中文与英文                                        | 不显示翻译键，失败有回退                               |
| 图标                                    | 核心静态图标；插件动态图标集合按功能边界加载 | 核心白名单；未知插件图标有带名称的中性回退        | 不以图标裁剪禁止插件工具或审批，说明视觉差异           |
| 其他外围功能                            | 保留同版可用Web行为，审计启动副作用          | 不提供语音/摄像头扫码/桌面专用面板等入口          | 多设备记录、模型选择、工作目录、插件工具信息等核心保留 |

完整候选的语音、摄像头等不是Vibes新增产品承诺，但只要导出中提供入口，就必须保持兼容并做有界验收；不能未经测试称“完整可用”。卸载外围时保留未保存编辑草稿、选择和必要输出位置，释放浏览器renderer/订阅；不得关闭远端terminal或停止Agent。JavaScript模块加载后通常仍驻留，报告运行资源释放，不声称代码卸载。

### 减少每次更新的工作

先保留官方现有虚拟列表、渐进文字呈现、diff窗口化/缓存及32000字符呈现上限。先采样再修改，不安排“重写虚拟列表”作为默认任务。使用固定事件回放记录未变化历史行render次数、Markdown解析次数、diff构建次数、rAF、long task及输入响应；优先收窄订阅、保留稳定引用、复用未变内容解析、对不可见外围停止绘制。审批、完成/失败和用户输入不能被降优先级或延迟到输出结束。

共同优化P保存为独立、可选择应用的补丁组，H/A/B的无P测量从干净快照构建，A+P/B+P再对照，禁止用不同时间的混合版本。共同优化P同时应用到A/B；若基线上游已经满足响应目标且没有额外热点，保留零补丁并提交采样证据。规范化状态同步可遍历必要记录，不把“减少更新工作”误解为禁止任何全量权威核对。不得删除canonical事件或靠漏渲染、静默截断获得性能。

## 宪章检查与预算

范围满足Explore与原UI边界；无账号、投稿、云端执行或新中继。原生配对所需浏览器连接材料是已有授权能力，秘密不得进入日志/URL；服务器工具执行仍由用户本地daemon控制。新增构建依赖在安装前说明并授权，不把source clone当依赖安装或功能验收。

当前main硬预算为普通JS gzip<21000 B、MDX<150000 B、媒体<16000 B、首页<40000 B、交互源<12000 B、优化图片<200KiB；保持数值及共享依赖计入原则。当前`scripts/script-budget.ts`把未分类JS计入普通预算，因此接入前需要正式新增受控助手分类，不能把vendor目录直接排除。`scripts/paseo-webui-manifest.ts`与资源清单共同验证全量资源、同步/异步闭包和未知文件；共享于普通浏览的依赖仍计普通预算，未声明资源失败。

实验G0在任何优化前冻结同版原始构建资源基线B0，将基线数值/资源摘要和预算公式保存到受版本控制的`third_party/paseo-webui/budget-baseline.json`，原始证据另存resources/evidence。助手初开目标≤B0初开压缩脚本的50%；总可达脚本预算≤B0总量，禁止通过把文件藏到懒加载目录规避。初开700000 B gzip为附加研究目标，源于旧路线目标，**不是main既有规则或新版必达承诺**。计划阶段不预先提高预算；G0根据实测清单记录数值，若硬预算分类需要超出此计划的调整，提交具体数据与取舍，不能静默放宽。

资源部署使用同源版本化路径`/vendor/paseo/<artifact-digest>/`，发布清单含完整文件哈希及许可；压缩算法、缓存命中和实际Content-Encoding分别报告。可选资源缺失时保留聊天并显示重试，不退回不兼容的旧chunk。检查懒加载public path、MIME、字体、WebGL/WASM/worker、Mermaid安全边界，以及运行中跨发布后再开旧可选功能的缓存策略；需要保留可达旧资源或明确有状态保护的重载路径，不允许资源清理破坏在用会话。

`public/_headers`当前仅允许同源connect且禁止自身frame。按实际接入和固定官方中继范围调整最小CSP；独立文档仅在专用路径允许宿主嵌入，Explore保持原保护。不能为通过试验整体开启任意connect、脚本eval或放宽Mermaid隔离。文档说明和对应安全回归与实现同批交付。

## 验证与交付

### 实验设计与因果归因

| 编号     | 配置                                                      | 回答的问题                               |
| -------- | --------------------------------------------------------- | ---------------------------------------- |
| B0       | 同版未改Web导出、匹配daemon                               | 官方基线；不算第三个候选                 |
| H        | B0+统一宿主/整助手延迟加载                                | 宿主接入额外开销，普通浏览是否零助手加载 |
| A1—A6    | H上分别只改变图表、终端、编辑器、语法、语言、图标加载边界 | 每项边界的独立收益；不是逐步累计值       |
| A        | H+已验证有效的按需加载组合                                | 完整候选首次/再次/可选功能成本           |
| B        | A共享边界+精简配置                                        | 排除外围功能的净收益                     |
| A+P、B+P | 两候选应用同样采样支持的渲染优化                          | 共同优化的收益及最终差距                 |

重点复核终端/编辑器/语法共享依赖，以及图表/语法组合；从B逐项加回主要功能，判断单项收益能否在组合中重现。参数均在`scripts/paseo-webui-experiment.ts`的受控配置与结果manifest中记录，不用任意环境变量产生不可追溯组合。

主实验固定官方WebUI/daemon0.7.2独立profile，两候选一致。不要求旧daemon0.5.0兼容，不恢复用户已取消的旧版直连测试，不绕过HTTP403。安装/升级不覆盖用户正在使用的实例或登录状态。加密中继配对与完整恢复移到接入后的端到端验收；未经验证不称远程使用通过。

已保存的B0源码、锁文件、原始导出与哈希不得覆盖。T004实际网络请求及完整依赖基线可在G1接入后补齐，但必须在拆包消融和声称收益之前完成；H与B0分开保存与统计。

### 负载、采样与门槛

- W0空会话、W1固定长历史（1000条事件/约1MB文本）、W2固定节奏流式消息+200次工具状态变化、W3多文件diff（50文件/10000行）、W4超长文本/单行代码/中文emoji/表格（覆盖31999、32000、32001及100000字符）、W5真实Luna多文件与批量JSONL任务。夹具脱敏且哈希固定；定义只作初始负载，G0记录实际事件格式后冻结，不能挑更轻输入帮助某候选。
- 每配置至少10次冷启动、20次暖启动；同设备交错随机顺序，单worker、独立profile/会话、独立缓存快照。冷启动网络/磁盘缓存清空，暖启动明确命中类型。统计中位数与p95、全部原始样本、失败/超时；小样本不作概率承诺。
- 首开时钟从点击到界面可操作，首次未配对与已配对缓存快照两种场景分开，B0采用等价入口触发，配对输入/模型等待另计；网络体积同时记录encodedBodySize和标准逐文件gzip，缓存命中不当作零原始成本。输入响应从真实键入事件到下一次可见呈现，p95≤200ms且不劣于B0；GC、profiler和诊断开销单独标注。
- 每最终候选100次受控循环：断网、长断网、半断开、daemon重启、订阅/历史补齐失败、乱序重复事件、回执丢失、审批中切会话、导航恢复、刷新恢复，各10次；另做主动断开、忘记后迟到事件各10次。测试在协议边界夹具与本地daemon中分别记录；不以socket连上认定恢复。至少99次自动恢复且零串会话/重复执行/误报，失败保留原因和可见重试；额外的主动断开/忘记场景以保持断开且无残留判定，单列20次，不混入100次自动恢复分母。
- 真实iPhone Safari分别覆盖后台10秒/60秒/5分钟/15分钟、锁屏、Wi-Fi切换、待审批返回，各至少3次/候选；长离开与真机不可用独立标为未测。桌面移动模拟只做补充，不折算真机通过率。
- 两候选各3次真实gpt-5.6-luna任务，使用相同提示、工作目录独立副本、权限/模型配置，验证多文件实现、测试失败再修复、6000条JSONL处理、审批拒绝/允许和停止。token/模型/工具耗时与UI开销分列；不提前批量跑模型。
- 外围资源100次开关/会话恢复前后检查连接/订阅计数、缓存范围与稳定后堆曲线；JavaScript堆不代表手机总内存，CPU代理不代表耗电。官方缓存有上限不等于实际使用量；缺能耗仪器即记录未知。

`scripts/paseo-webui-results.ts`只汇总已有数据；`resources/evidence/012-paseo-webui-loading/<run-id>/`保存配置、版本、构建清单、trace、CSV、截图、失败及覆盖清单。正式UI验收复用Playwright；上游已有stream-smoothness与diff-performance测试可复用负载与断言，接入现有测试入口，不维护第二套E2E框架。真实浏览器与手机观察另留证。

### 停止点与选择

固定版本/B0原始导出及部分同版运行证据→G1直接接入探针→T004完整基线与配置冻结→G2 Mermaid生产拆包探针→G3单项与组合→G4两候选共同运行优化及真实验收→G5选择与交付。G2要求普通聊天不请求图表chunk、展开才请求、缓存复用、加载失败可重试、真实前缀/CSP下成立；失败先定位静态引用/public path，不立刻换构建器。G1/G2未过不展开全部外围改造。

核心正确性是淘汰门槛，不用加权分数抵消。对通过者并列性能、功能损失、恢复、补丁文件数/行数和维护代价；差异未超测量波动时优先改动更少的完整按需版，精简版只有实测收益足以解释功能损失时推荐。两者都未达到要求则报告瓶颈及最小后续方案，不回引assistant-ui。

维护验证包括新干净快照完整重放补丁、锁文件/产物可追溯，以及对已知相邻上游版本相关路径的变更重叠分析；尚无新版本时不宣称完成未来升级验收。最终生产只保留选定配置，实验结果保存，实验专用开关不能开放给普通访客。
