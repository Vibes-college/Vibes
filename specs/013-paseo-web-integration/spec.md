# Paseo原生助手：安装、连接与持续使用

## 讨论状态：先厘清目的，再选择方案

用户补充要求：先通过多轮具体场景确认真正需求，解释性能、成本、维护、稳定性的取舍，再实施。下面US/FR/SC是讨论草稿，不是已批准的功能清单或数值承诺；旧项目存在过的功能也不自动成为新需求。

已确认：建立新分支和Draft PR，吸收并保留过去经验，优先讨论复用官方Web协调能力，按用户感知分阶段评价，不先为减包而裁剪。

待讨论：访客最终想得到什么；为什么需要本地Agent；Chat/Build原本解决什么问题；compact/full/standalone分别是否必要；愿意让用户完成多少安装、配对和目录设置；可接受的维护与体验代价。先回答前三类场景问题，再据答案逐轮收敛，不一次要求用户填写技术问卷。Chat后端兼容性是已发现的成本，不代表现在要用户直接选技术架构。

## 用户与核心路径

面向在Explore发现作品、希望通过自己电脑上的Agent讨论或动手的普通访客。Vibes提供作品入口、公开上下文和轻量接入外壳；Paseo提供完整聊天工作台及其连接、会话与操作协调。沿用Explore现有页面与阅读体验。

- US1（P1）首次使用：点击助手立即看到安装与连接引导，前往电脑安装官方App或CLI、准备可用Agent，再完成配对。阅读引导期间后台准备助手；已安装用户可直接连接。任一步失败保留当前步骤、说明与重试入口。
- US2（P1）连接后做事：使用真实模型与会话，编辑草稿、发送、查看工具与审批、停止；按需把当前公开作品附入草稿。顶部参考旧项目的极简图标，支持compact/full及独立页面；Chat/Build语义须满足下述兼容边界。
- US3（P1）继续浏览再回来：收起助手后继续搜索或阅读，切作品、语言、历史返回后重开，回到原会话、草稿与阅读位置。刷新、离线重连及从浏览器后台返回时，恢复结果可辨认，未确认的操作不会被盲目重发。
- US4（P1）持续使用：聊天、长记录滚动、工具操作和反复开合保持跟手；助手收起后Explore仍顺畅。维护者能依据分阶段证据定位问题，而非以包体大小代替体验判断。

各故事独立验收：US1完成未安装/已安装/失败重试路径；US2完成真实会话及拒绝/允许审批；US3覆盖在途操作与草稿的恢复；US4按同设备、同输入的对照结果验收。先完成接入与正确性，再针对实际退化优化。

## 功能要求与验收

- FR001：用户首次主动点击前，不下载、初始化Paseo专用资源或探测电脑；Explore的搜索、阅读和媒体行为保持现状。
- FR002：点击即展示轻量外壳和清楚的当前状态；安装、准备Agent、配对和可聊天是不同步骤。预加载与用户阅读引导并行，不固定等待几十秒，不伪造安装完成或可操作状态。
- FR003：已安装或已配对用户直接进入连接/恢复路径；缓存失效、慢网、离线、下载失败、加载中收起与重试均有明确结果。预加载仅准备网页资源，不代替用户配对或启动远端任务。
- FR004：采用固定版本的Paseo Web完整应用协调能力。探测、连接所有权、重连、过期连接、订阅恢复、历史补齐、重复与迟到事件和在途操作核对由同一原生运行体系负责；Vibes不再维护第二套连接或会话真相。
- FR005：保留旧界面的极简顶部、compact/full和独立使用体验。普通界面不展现工作区管理、文件树、终端及复杂导航，但保留必要的目录选择、模型设置、会话、工具结果和审批；隐藏入口不等于删除底层能力或撤销权限。
- FR006：若确认需要Chat/Build，应是用户可理解的工作方式，不能只改名称或提示词却承诺权限隔离。旧项目Chat包含定制后端能力；[NEEDS CLARIFICATION: 用户希望Chat/Build分别解决什么问题，确认目的后再比较普通官方会话与定制隐藏工作区的成本。] 确认前不实现模式行为。
- FR007：compact/full切换保留会话、草稿、滚动位置和焦点；手机采用适合视口的全屏布局。独立页面可直接打开并完成同一配对/会话路径；新标签页复用连接与否以官方能力和验收为准，不承诺跨标签共享内存实例。
- FR008：用户主动附带当前公开作品的标题、链接及可见简介到可编辑草稿，发送前可取消；切作品不自动发送或覆盖草稿。不把网站内容提升为系统指令，不默认发送私有目录、配对信息或完整阅读历史。
- FR009：真实模型、会话、流式消息、工具状态、审批允许/拒绝和停止走原生操作路径。恢复或结果未知时明确区分已有记录与已确认状态，不静默重发发送、审批、停止或新建操作；如原生行为达不到要求，记录缺口再决定，不重写客户端补洞。
- FR010：收起只改变展示与必要的活动信号，不取消任务、不忘记设备。保留必要连接及状态更新，暂停无用显示工作；恢复显示后由原生机制核对。仅设置CSS隐藏不能作为后台成本通过证据。
- FR011：站内导航、重开和浏览器生命周期不创建重复根、连接、监听器或提交。当前会话、未发送草稿与位置在支持的恢复路径保留；存储被清除或浏览器主动丢弃数据时明确说明限制，不能显示虚假的恢复成功。
- FR012：断开、忘记设备和收起含义清楚。主动断开不被前台事件自动连回；忘记清除该设备的配对材料及约定本地缓存，不影响其他设备，不删除电脑文件或声称远端任务被终止。
- FR013：配对使用官方连接机制；浏览器配对材料遵循原生存储边界，不进入Git、日志、分析或公开URL。生产环境的连接、嵌入、插件和资源限制必须实测，禁止用开发服务器成功代替上线兼容性。
- FR014：图表、富文本、语法、多语言与图标先保留原生能力；只按普通用户路径简化可见入口。出现实测退化后再决定是否拆包、减少渲染或限制资源，并重新验证受影响行为。
- FR015：安装引导覆盖实际支持的电脑系统、官方安装入口、Agent准备及配对完成标志；手机明确需要一台运行Paseo的电脑。上游版本不兼容时提供实际可用的升级指引，不凭旧版本测试声称全部App/CLI可用。

### 可观察的成功标准

以下数值为拟议验收门槛，不是已测结果。正式采样前在plan中固定环境、负载、样本、统计和误差处理，不能见结果后修改门槛以求通过。

| 编号  | 用户结果                 | 验收标准                                                                                                                                                                   |
| ----- | ------------------------ | -------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| SC001 | 点击立刻有反馈           | 指定桌面和手机测试配置各20次点击，点击到首个可见外壳p95不超过200ms；未安装与回访分别记录到可聊天的分段耗时                                                                 |
| SC002 | 引导不增加额外等待       | 安装期间预加载成功后不重复完整下载；已安装用户不被强制留在引导或等倒计时；慢网与失败可恢复且不丢步骤                                                                       |
| SC003 | 输入和操作跟手           | 同设备、同版本官方Web对照下，打字、按钮、工具展开的呈现延迟p95不超过200ms，且超过官方对照的部分不大于50ms；同负载滚动长帧占比不多于对照5个百分点                           |
| SC004 | 收起后Explore仍顺畅      | 相同页面与操作下，收起后的搜索/点击p95较从未打开助手时增加不超过50ms，长帧占比增加不超过5个百分点；空闲、持续输出和待审批分别测                                            |
| SC005 | 重开、切页、恢复不丢状态 | 20轮开合与站内导航后，原会话/草稿/位置全部一致，无额外完整资源下载或重复提交；暖重开可见原内容p95不超过200ms，连接待核对时如实显示状态                                     |
| SC006 | 断线不会重复做事         | 发送、工具进行中、待审批、停止待确认四种状态覆盖断网、刷新、后台返回；对每项核对真实会话与操作次数，无重复提交、错会话审批、旧事件覆盖新状态；不声称停止等于全部子进程结束 |
| SC007 | 长时间不越来越卡         | 固定负载持续60分钟并覆盖30轮开合，结束时重复SC003/SC004仍满足门槛；静置后连接/监听器不逐轮增长，连续增长的CPU或内存必须定位并解释后才能验收                                |
| SC008 | 真实可用并可交付         | 真实Paseo、真实Agent、真实浏览器完成主路径及恢复；整站必要检查、原有预算、独立审查与同SHA预览通过；手机模拟和iPhone真机结果分别报告                                        |

包体、网络传输、解析/初始化、CPU、内存、长任务与帧耗时用于解释以上结果。包体也可能影响解析和初始化，不能说它只影响下载；预加载不免除主线程和后台资源验证。首个回答须区分模型/网络等待与收到数据后的展示延迟。

## 明确不做

不延续assistant-ui加自有会话适配路线，不先进行大规模裁剪或重建渲染器，不以“包体减半”作为成功标准。不开放公众或Agent编辑Vibes，不增加账号、云端执行服务、终端工作台、编辑器、文件管理或任意网站导航。不默认维护定制Paseo daemon，不自动升级或替换用户现有服务，不把隐藏UI当作安全沙箱。不关闭、合并或清理PR #10/#11及其资源。

## 端差异

桌面验证鼠标、键盘、焦点与两种面板尺寸；手机验证320px、软键盘、触摸滚动、前后台与锁屏。浏览器模拟不能证明真机挂起、发热或耗电。无JS继续完整浏览Explore，助手提供静态说明及官方入口；CLI仅作为电脑安装/连接选项，页面不执行本机安装命令。
