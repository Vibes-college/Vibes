# 按用户操作路径组织功能文档

## 用户与核心路径

用户与维护Agent从功能索引选择要完成的任务，阅读一篇文档即可找到完整操作、结果、涉及文件、验收、测试、依赖和已知问题。用户确认按操作路径划分，访客两篇，维护者另行分组。

## 功能要求与验收

- FR-001：模板采用用户提供的七个栏目：一句话说明、用户操作路径、涉及的文件、验收标准、对应的自动化测试、依赖的其他功能、已知问题/待办。
- FR-002：访客路径为浏览与搜索作品、阅读作品详情；维护路径为维护作品内容、检查与发布网站、规划开发与维护文档。手机、语言和异常行为并入路径，不单独作为功能。
- FR-003：移除重复的发布记录和实现细节，命令/配置/规则以operations与technical文档为准；功能说明链接到准确的文件和测试。
- FR-004：不改写001/002历史正文，通过当前文档legacy-feature-ids接续旧编号；编号格式、重复归属、已合并规格缺失对应文档及来源缺失必须失败。
- FR-005：验收勾选只代表本次真实执行，旧证据注明日期，未执行项保持未勾选并解释。正文重写不推断产品重新验收。
- FR-006：按用户参考图，以简短Mermaid图展示用户动作、实际系统处理、可见结果及失败分支，源码可追溯；不照搬参考系统实现。
- SC-001：功能索引恰有五个当前文档且按两种使用者分组；全部采用新模板栏目，路径和自动测试名称可核对。
- SC-002：新增旧编号映射的成功与失败测试，并通过npm run check；原冻结与缺失文档保护仍有效。

## 明确不做

不改网站行为、内容数据、依赖、CI运行配置，不部署、不创建或合并PR。不重新运行整站浏览器来证明纯文档重排。

## 端差异

文档检查本地和CI使用同一规则；功能文档明确手机、无JS和语言边界，但不宣称真机或读屏通过。
