## 先做一张能让人报上名的卡片

你准备办一场周末读书会，让 Agent 做了一个报名页面。标题会飞入，卡片会抬起，按钮按下去还会弹一下。你把链接发给朋友，对方点了“报名”，等了一会儿，又点了一次。

“到底报上了没有？”

这一刻，页面已经有了动效，却缺少一句最需要的回答。按钮弹了一下，只能说明收到了点击；名额有没有保留、资料有没有提交，还要等后面的任务给出结果。**学习网页交互，先学会辨认用户正在等什么。**

这篇文章用一张活动报名卡作练习。读到最后，你应该能给 Agent 一份清楚的需求，指出一个效果为什么适合这里，并亲自验证它是否帮助人完成了报名。你不需要会写组件代码，但要参与这些判断。

先准备一组练习内容：活动叫“周末共读”，有“周六上午”“周日下午”两个场次，有一段活动介绍、三条常见问题，以及姓名输入和报名按钮。这些是教学用的虚构数据。你也可以换成自己的预约、课程报名或资料保存页面，保留同样的任务结构。

把下面这段交给你正在使用的编程 Agent：

> 在当前项目里做一个“周末共读”的报名练习页，沿用项目现有技术和样式。放活动介绍、两个场次、姓名、报名按钮和三条常见问题。先完成静态布局与基本操作，暂时不加装饰动画。没有真实报名服务时，在页面明确标注“模拟报名”，提供成功和失败两种可切换的演示结果。请给我可以实际操作的预览入口。

打开结果，先走一次“看介绍 → 选场次 → 填姓名 → 报名”。观察有没有一个地方让你停下来猜。暂时把问题写下来，后面我们会逐个处理。

## 按钮按下去以后，界面欠用户四个回答

把练习页停在提交前。先自己决定：如果报名需要等一会儿，按钮上应该出现什么？如果最后失败了，刚填的姓名应该去哪里？

这两个决定比按钮的圆角更早影响体验。打开[有层级的基础按钮](/zh/works/great-ui-button/)，你会看到实色、描边和轻量样式的区别。它们让同一区域的主次操作有了层级：此刻最重要的“报名”值得醒目，“查看活动详情”可以安静一些。几个按钮同时抢眼，用户就得重新阅读每个标签才能决定下一步。

再看加载状态。旋转图标让人知道任务仍在处理，暂时禁止再次触发可以避免连续提交。但原作的按钮没有报名业务，不能自己判断任务成败。把它带进页面之前，先用这张表说清楚结果：

| 时刻     | 用户需要知道什么           | 报名练习里的表现                           |
| -------- | -------------------------- | ------------------------------------------ |
| 可以报名 | 下一步会发生什么           | 按钮写“报名周六上午场”，已选场次可见       |
| 正在提交 | 点击收到没有，还能不能再点 | 显示“正在提交”，停止重复触发，保留所填内容 |
| 报名成功 | 哪件事完成了，接下来做什么 | 显示已确认的场次与结果说明                 |
| 报名失败 | 哪一步没完成，怎样继续     | 说明未完成报名，保留姓名和场次，提供重试   |

成功提示必须由实际结果触发。练习页可以故意模拟成功，但要保留“模拟报名”的说明；动画播放完毕不是报名完成的依据。

现在让 Agent 按这张表补齐四种状态。把演示设为失败，连续点两次报名，再重试。你应该能看到内容保留、操作不会重复执行、结果说明与这一次操作一致。若只出现一个转圈图标又回到原样，就把这个现象原样告诉 Agent。

你刚刚做的是**状态设计**：先规定界面在不同处境下该表达什么，再让颜色、文字和运动表达同一件事。

## 看懂一个动效，只需要先抓住三件事

回头看报名卡。你希望鼠标移上去时，卡片轻轻抬起。怎样向 Agent 说清楚“轻轻”，又怎样判断它有没有必要？先把注意力放在三个可以观察的地方。

**谁触发了变化？** 是鼠标进入、手指按下、键盘操作、滚动到这里，还是任务结果到了？触发条件决定用户能否主动控制它。只在悬停后出现的报名入口，到了手机上就需要另一条明确路径。

**什么发生了变化？** 位置、大小、透明程度、容器高度，各自传递的关系不同。下面这些名字遇到时再记，先看它们做了什么：

| 画面变化                     | 可以用来解释什么               | 在报名页怎样判断                         |
| ---------------------------- | ------------------------------ | ---------------------------------------- |
| 位移：从一个位置到另一个位置 | 方向、归属、同一对象的位置改变 | 场次高亮移动后，能否看清选到了哪里       |
| 渐显：从透明到可见           | 某条信息出现或被替换           | 结果文字是否及时出现，最后能否完整阅读   |
| 高度变化：展开时让出空间     | 隐藏内容属于哪个入口           | 答案展开后，后面的题目是否自然下移       |
| 缩放：物体短暂变大或变小     | 按压感、强调                   | 手指按下时有反馈，文字和点击区域仍稳定   |
| 遮罩：逐步露出或遮住内容     | 揭示范围、页面切换的先后关系   | 是否确实需要整页遮挡，还是局部更新就够了 |

**变化结束后，用户得到了什么？** 卡片升高了，但不能点击，也没有新增信息，它可能只承担装饰。装饰可以存在，只是要按页面目的判断是否值得持续吸引注意。

比较[有分隔线反馈的图片卡](/zh/works/great-ui-card/)时，留意线条如何提供反馈而不把文字挤走。放到活动页面，先确定整张卡是否真的是活动详情入口。如果只有里面的报名按钮能操作，整卡都像按钮一样弹起就可能让人误判。运动的强弱要和可执行的动作对得上。

把任意一段录屏暂停在开头、中间、结束，各用一句话描述画面。这三个句子，加上触发条件，已经比“照着做一个高级感的动效”更容易让 Agent 理解。

## 答案该展开，还是整块换掉

报名页开始变长了。你想放三条问题：“在哪里集合”“需要准备什么”“报名后如何修改”。把所有答案直接写出来很清楚，但也会让首次浏览变长。可以试试[折叠问答](/zh/works/great-ui-accordion/)：标题留在原处，用户按需打开答案。

这个模式叫渐进披露，意思是先给足够的线索，再让需要的人取出细节。它是否好用，首先取决于标题。写成“其他说明”，读者仍要打开才能知道里面有什么；写成“报名后如何修改”，他已经能判断是否需要阅读。

原作同一时间最多打开一项，初始展开第二项。打开新答案会关掉旧答案。对“只找集合地点”的人，这样很紧凑；对“同时对照两个场次安排”的人，来回开关会增加记忆负担。

让 Agent 用同一份内容做单项、多项两个版本。先找一条答案，再比较两条答案。第二个任务如果总要反复切换，就值得允许多项同时展开，甚至直接展示需要比较的内容。选择来自阅读任务，不能只凭哪种展开更好看。

展开时，答案区域从没有高度逐渐长到容纳文字的高度，同时变得可见。后面的题目跟着下移，读者能看出新空间从哪里来。把答案换成三倍长的中文，再缩到手机宽度：高度应跟着内容走，不能仍按短英文样本留一块固定空间。原作点击答案区域也会收起；接入时要检查选文、复制、点链接会不会误关答案。

如果内容换成“活动介绍 / 讨论 / 往期照片”，它们是同一活动的几组平级资料，一次主要看一组，可以比较[滑动指示的内容标签](/zh/works/microkit-sliding-content-tabs/)。它让同一块背景移动到选中的标签下方，再替换局部内容，页面其他部分保持原位。

两者的区别在于阅读关系：问答让某个标题的细节展开，标签让几组内容轮流占据一个区域。必须并排比较的信息，藏进标签后同样会来回切。这个标签原作已有选中语义和减少动态样式，但左右方向键切换与长短内容适配仍需接入时补齐；不能从一段顺滑录屏推断所有操作都已完成。

## 搜到了，不等于选中了；收起来，也不等于保存了

现在把两个场次扩展成几十个活动。直接拉一长串选项不好找，可以引入[能搜索，也能确认的选择框](/zh/works/beui-combobox/)。如果始终只有两个选项，直接展示通常就够了；搜索框会额外增加输入和打开列表的动作。

打开 beUI 的案例，注意它把三个状态分开放置。输入框里的查询决定“我在找什么”；活动高亮表示“我准备选择谁”；勾号表示“我已经选了谁”。输入“product”只是缩小候选，确认 Product team 才改变结果。关掉未完成的查询，会恢复原先已选的名称。

把它改到报名练习里：先选“周六上午”，重新打开，搜索一个不存在的场次，再关闭。理想结果是仍保留原来的选择，而不是把刚才的搜索词当成报名场次。接着清空查询，候选应该重新出现。这样一来，你就验证了“寻找”和“确认”之间的边界。

换中文内容时，把真实名称和想支持的简称一起给 Agent。例如名称为“周六上午共读场”，希望搜“周六”能命中；若还希望拼音或另一种叫法也能命中，要明确提供规则。原作英文样本没有证明它会自动理解这些别名。没有匹配也和读取失败不同：前者可以改关键词，后者需要说明数据没取到并允许重试。

再看[就地展开的时长编辑器](/zh/works/rare-ui-duration-picker/)。它适合拿来做另一个练习：编辑活动时长。原作把紧凑的时长展开成小时、分钟输入，确认后合拢；输入越界会被限制，并通过晃动提醒。

这里最容易误判的是“确认”二字。固定实现的修改会逐次交给外部，确认负责回调和收起；它没有替你完成服务端保存，也没有内置 Escape 取消并恢复旧值的完整行为。如果你的产品需要“取消就回到编辑前”，要单独提出“已保存值”和“正在编辑值”的区分。

先让 Agent 把时长从一小时改成两小时，再取消，观察显示是否回到一小时。接着确认并模拟保存失败，观察能否继续修改。你学到的不是某种输入框样式，而是三个时刻的不同承诺：**正在编辑、确认意图、保存完成。**

## 调节节奏时，一次只动一个地方

按钮和问答能用了，你觉得展开还有点生硬。可以开始调运动，但先保留一个原版本，用同样的内容和操作作比较。

动效的“快慢”至少包含三件事：开始前等多久、变化持续多久、途中怎样加速和减速。延迟决定何时开始回应；时长决定变化占用多少时间；缓动决定相同时间里各段走得快还是慢。弹簧则还可能产生回弹，像物体越过落点后再收回来。

以问答为例，原作展开时长是0.3秒。为了感受差异，可以让 Agent 另外提供0.15秒和0.6秒两个练习版本。这两个数只是便于比较的试验值：前者是原作的一半，后者是两倍，并非所有网页都该采用的标准。

三版都做同一个任务：连续打开三条答案，读最后一条。较慢的版本也许在单独观看时显得舒展，连续查阅时却让每一次点击都多等一段。较快的版本可能更利落，也可能快到难以辨认内容从哪里展开。把注意力放在阅读是否被打断，再决定采用哪一种。

不要同时改时长、回弹、文字大小和留白。四个地方一起变，感觉更好也难以知道是谁起作用。先固定内容和布局，只比较时长；之后再比较运动曲线，最后处理间距。

若动画过程中还能再次操作，也要试一次。快速从第一个标签点到第三个，界面应收敛到最后一次选择。高亮停在第三项、文字却来自第二项，问题在状态衔接，继续调慢动画只会把问题藏得更久。

“更顺滑”可以改写成具体要求：按下后立即有反馈；同一对象的移动连续；连续操作不会留下旧内容；用户要读的文字尽快稳定。这些要求都能在预览里观察。

## 从一块内容扩展到整页，先算阅读的代价

报名卡已经清楚了。你还想让活动介绍随滚动逐字亮起，再给页面加一段开场转场。它们的影响范围更大，选择前先走一遍读者的路径。

[滚动文字揭示](/zh/works/great-ui-text-reveal/)把滚动进度映射到文字的显露程度。滚得越远，更多文字变清楚。这和“进入屏幕后自动播一遍”不同：读者的滚动动作参与了节奏。它适合拿来练习一句有重点的介绍，但如果报名地点和时间也要滚很久才看全，读者就在为获取必要信息付出额外动作。

把同一句活动介绍做成普通文字和滚动揭示两版。从页面顶部找到报名时间，再复述活动内容。你可能喜欢动态版的气氛，也可能发现自己只是在多滚几下。保留它的理由应当落到这次体验上；必读信息仍要容易到达。

[错峰页面转场](/zh/works/great-ui-staggered-page-transition/)展示了另一种时序：先遮挡，再切换内容，最后揭开。错峰意味着各块不会同时开始，它能让一次整页变化有先后。但连续访问三个页面时，这段等待也会重复三次。让 Agent 说明新内容何时准备好，并检查切换中断或加载失败后能否继续操作，不能只按一个计时器假设下一页已就绪。

[从一点展开的主题](/zh/works/great-ui-circular-theme-provider/)则把触发位置与整页颜色变化连起来：人从这里切换，新的主题从这里扩散。应用到自己的页面，最终的文字、背景、输入框都要属于同一套主题；局部动画结束后仍有一块旧配色，说明主题状态还没统一。

这些效果不必全装进报名页。你可以另开练习比较它们，再把有理由保留的带回项目。影响范围越大，越要把阅读、导航和返回操作一起考虑。

## 把观察写成 Agent 能接住的修改要求

做完前面的练习，你已经积累了一组比“好看一点”具体得多的判断。现在打开任一案例的“改造设计”，选择最接近需求的目标，再用“生成修改任务”或“用这个效果”补充位置和要求。案例会提供原作、固定源码、素材和检查依据，你需要补上自己的内容和取舍。

下面是一份可以改写的任务。它借用问答的展开关系，同时明确活动页需要改变的行为：

> 使用位置：周末共读报名页的常见问题区。读者报名之前要核对集合地点和修改报名方式，有时需要同时查看两条答案。
>
> 参考：本合集的折叠问答。保留标题常驻、答案从标题下方展开、后续内容自然下移的关系。
>
> 内容：请使用我提供的三条中文问题与完整答案，其中一条带有详情链接。必须知道的报名条件放在问答外，直接可见。
>
> 行为：允许多条答案同时打开，只点对应标题才关闭。点击答案内链接、选文和复制不应收起。键盘能完成同样操作，关闭的答案不能继续接收焦点。手机上长答案完整换行，减少动态效果时直接显示结果。
>
> 交付：给我实际预览，说明哪些参考行为保留了、哪些按上述要求改变了。我会连续打开两条、复制其中一段，再用键盘和手机宽度重复操作。

这份需求没有要求你写出高度动画代码。它说明了任务、参考中值得保留的关系、真实内容、需要改变的规则，以及判断完成的方法。Agent 有实现空间，你也有检查依据。

结果不对时，反馈同样要落在现象上。例如：“手机宽度下打开第二条答案，最后两行被截掉；我需要完整阅读，也不希望答案内部再出现一根滚动条。请修复后用同一段长文字给我看。”这比“响应式再优化一下”少了许多猜测。

如果 Agent 把动画做得像原作，但仍在点击答案时收起，就指出它保留了不适合当前任务的关闭规则。案例是帮助判断的参照，每一个保留与改动都应能说出理由。

## 做完之后，用这五次操作检查自己

回到开头的报名练习页。先不要给朋友解释哪里该点，让他从活动介绍走到报名结果。你观察停顿，记录他以为发生了什么，再和页面实际状态比较。

自己再做五次检查：

1. **把内容变得难放。** 用长姓名、相近的场次名称和长答案，缩到手机宽度。核对标题、当前选择与按钮是否完整可辨。
2. **把顺利的一次改成失败的一次。** 让 Agent 在练习环境模拟提交失败，再重试。确认输入保留、失败原因可读，也没有把动画结束当作成功。
3. **把鼠标放开。** 用 Tab 找到入口，再用对应按键完成选择、展开和提交。你应该一直知道焦点在哪里，关闭内容后不会误进看不见的区域。
4. **把操作加快。** 连续切换标签、展开问答或点击提交。最后的选项、内容和结果应该一致，也不能重复执行同一次提交。
5. **把动态关掉。** 让 Agent 提供减少动态效果的版本，或用系统相应偏好检查。去掉移动和回弹后，文字、状态与操作仍应让人完成同样任务。

原作演示不一定具备这五项能力。它们是你把参考带进产品时需要逐项核对的要求，尤其要区分“录屏中看到了”和“自己的页面已经做到了”。

如果报名过程确实变成了多步任务，再看[分步状态清单](/zh/works/great-ui-deployment-checklist/)。它适合解释哪一步等待、完成、跳过或失败。原作使用固定延时演示预设结果；接入后每一步都要对应真实状态。只是一次很短的提交，就地说明结果通常更容易读，不必为了展示清单而制造步骤。

最后，把同一套方法换到“保存个人资料”页上。先不打开新案例，自己写出等待、成功、失败的表现，再决定哪里需要运动。如果你能说明这些选择，已经开始把方法带到另一个任务里了。

## 接下来，按问题挑一件继续练

先把报名卡做通，再根据当前问题进入独立案例。每件的“拆解设计”解释原作，“改造设计”提供练习目标；需要连接多个组件时，再从“串联设计”看它们各自承担什么。
