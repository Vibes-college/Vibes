## 用图形回答问题，而不只是装饰数据

Observable Plot 是一个用于探索性数据可视化的 JavaScript 库。它围绕图形标记、比例尺和变换组织图表。理解它的起点是数据与视觉编码的对应关系：一行记录中的字段，如何变成位置、长度、颜色或分组。 [查看来源](https://observablehq.com/plot/)

## 先写问题，再选图形

如果问题是“谁更多”，比较长度通常比比较面积直观；如果问题是“随时间怎样变化”，连续的时间轴更有帮助。这些是编辑层面的设计建议，不是库自动保证的结论。工具降低绘图成本，但图表是否诚实仍取决于选择。

### 三个值得观察的角度

下面是 Vibes 的阅读提示，用来组织问题与比较材料。

| 观察角度 | 先问什么       | 阅读时留意         |
| -------- | -------------- | ------------------ |
| 比较类别 | 条形等可比长度 | 排序与基线         |
| 观察趋势 | 按时间组织数据 | 缺失区间与时间尺度 |
| 寻找关系 | 两个变量的位置 | 异常值与混杂因素   |

## 带着一个小练习继续探索

准备一张十行左右的简单数据表，先写出你希望读者回答的唯一问题。做出第一张图后，隐藏标题请别人解释它。若答案与问题不一致，优先修改编码和注释，而不是添加更多颜色。

### 把阅读变成自己的判断

1. **先理解材料。** 用自己的话解释作品要解决的问题，保留你尚未理解的概念。
2. **再记录观察。** 把亲眼看到的结果与自己的推测分开，写下形成判断时的条件。
3. **回到原始来源。** 遇到影响结论的细节，继续阅读原文、文档或完整节目，不只依赖这份导览。

> 阅读笔记：有价值的探索，既包括发现新的可能，也包括知道一个结论适用于什么条件。
