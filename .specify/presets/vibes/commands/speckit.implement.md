# implement

用户输入：`$ARGUMENTS`。结合当前对话理解请求，遵循AGENTS的任务路由与授权边界。

仅当`.specify/extensions.yml`存在时读取`.specify/presets/vibes/references/hooks.md`，在本阶段执行前后处理`before_implement`与`after_implement`；未配置时静默跳过。

1. 运行`.specify/scripts/bash/check-prerequisites.sh --json --require-spec --require-tasks --include-tasks`定位spec、plan、tasks，只加载当前工作所需内容。用户已确认的范围与授权持续有效。
2. 查看适用于当前阶段的清单。只有实际阻塞当前工作的需求缺口或明确指定的人工审阅门槛才暂停依赖步骤；未勾选的辅助项不自动阻塞。能在已授权范围内修复的规格问题直接处理；需要用户决定或审阅者结论时再等待。自定义清单及其勾选状态只读，不代替审阅者确认。
3. 按真实依赖执行tasks；复用现有结构和工具，不逐语言扫描或创建无关ignore配置。仅当本次引入相关文件类型、工具或实际遗漏会影响工作时调整配置，不顺便重构。
4. 按风险实施必要测试和修正，不强制所有任务使用TDD。失败只暂停依赖失败结果的步骤：修复本任务造成的问题并重跑受影响检查；其他独立任务可继续。仅缺少必要信息、权限或外部条件时等待用户，外部/已有问题据实报告，不掩盖失败或无限重试相同操作。
5. 按实际完成状态更新tasks；按有意义的阶段报告进度。完成已授权范围内实现、必要验证、相关文档、保存与PR更新，不在首版实现后无理由停下。
6. 按docs/system/checks-and-release.md选择并完成必需检查。已有通过结论仍有效时不因新对话或阶段切换重复检查；新变化、失败或未解决风险使证据失效时复核。需要完整验收的交付仍完整执行，保留必要独立审查和用户合并决定。

完成标准：范围内任务和必要检查完成，当前说明与实现一致；实现、PR合并、部署状态分别据实报告。用户指定的阶段停止点、授权边界和外部阻塞继续有效。
