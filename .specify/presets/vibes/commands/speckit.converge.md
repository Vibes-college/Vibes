# converge

用户输入：`$ARGUMENTS`。结合当前对话理解请求，遵循AGENTS的任务路由与授权边界。

仅当`.specify/extensions.yml`存在时读取`.specify/presets/vibes/references/hooks.md`，在本阶段执行前后处理`before_converge`与`after_converge`；未配置时静默跳过。

1. 运行`.specify/scripts/bash/check-prerequisites.sh --json --require-spec --require-tasks --include-tasks`。用于implement之后的当前未冻结规格；冻结内容通过新规格承接。
2. 从需求、验收、计划决定和现有任务建立范围，再检查相关代码与证据。仅检查已定义的工作；不把未承诺的优化、业务KPI或个人偏好追加为任务。用户最新明确决定与项目边界优先，过时规格先据实指出。
3. 缺口需说明需求引用、实际行为、位置与后果。对照全部已有任务，按需求引用和实际工作去重；已由未完成任务覆盖的缺口引用原编号，不新增任务。已勾选却被新证据证明未满足时，说明证据失效原因，仅在没有现存修复任务时追加一项修复。
4. 只对尚未记录的可执行缺口在tasks末尾追加Convergence段，使用后续稳定编号；保留既有任务和有效证据。本阶段不修改代码或冻结正文。
5. 无新增缺口时不写空段落。仍有未完成任务或未满足验收时明确报告待完成，零新增任务不代表已收敛；全部要求满足才报告收敛。

完成标准：剩余工作有唯一、可追踪的任务或明确外部阻塞。已授权完整实施时继续处理剩余任务；只因新增修改、失败或证据缺口再次核对，不无变化循环追加任务。
