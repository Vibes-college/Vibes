# clarify

用户输入：`$ARGUMENTS`。结合当前对话理解请求，遵循AGENTS的任务路由与授权边界。

仅当`.specify/extensions.yml`存在时读取`.specify/presets/vibes/references/hooks.md`，在本阶段执行前后处理`before_clarify`与`after_clarify`；未配置时静默跳过。

1. 运行`.specify/scripts/bash/check-prerequisites.sh --json --paths-only`定位当前规格，仅读取与未决事项相关的spec、现状和必要约束。冻结spec需要新规格承接，不能直接改写。
2. 只问答案会实质改变范围、成本、权限、正确性或验收方式的问题。先用已提供信息和可查代码解决事实问题；无有效问题时直接报告并继续已授权阶段，不为跳过澄清制造警告。
3. 独立问题每轮合并最多3个；答案存在依赖时逐个询问。用中文完整说明问题及影响，有合适默认时给建议。回答以含义清楚为准，不限制词数；只在实际含义仍不明确时追问。
4. 用户回答后把决定更新到相关规格段落，移除矛盾旧描述，不重复写多份问答流水账。必要时更新内置requirements.md的实际质量结论；自定义清单的审阅者勾选状态保持不动。
5. 核对受影响的需求、路径与验收；新答案不影响的内容和有效证据保留。缺少必要决定时暂停依赖工作，其他独立工作继续。

完成标准：剩余重要歧义已消除或准确标为待决定；已授权的后续阶段无需再次征求继续许可。
