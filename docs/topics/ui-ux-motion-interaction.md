# 《Vibe Coding 网页动效与交互》目录与候选清单

**已确认：合集名称，以及同一案例可以同时讲动效和组件。以下分类、候选取舍与学习顺序是供讨论的首版策划，不表示网站已经改名、重排、删减或发布新内容。** 上层能力地图见[UI/UX学习主题](ui-ux.md)，网站现状见[学习交互作品](../features/great-ui-learning.md)。

合集围绕一项广泛、可识别的技能组织，容纳数百件精品案例。Great UI、Rare UI、beUI等是素材来源；每件案例说明本例值得学习的设计决定、组件行为和Agent协作方法。来源库不会各自变成一套重复课程。

## 一、可持续扩充的内部目录

先用十个一级分类，增长后按实际内容增加二级分类；不预先建立空章节。分类服务查找，推荐顺序服务学习，二者可以共用同一件案例。

| 一级分类                 | 可扩充的内容                                                             |
| ------------------------ | ------------------------------------------------------------------------ |
| 按钮、链接与选择输入     | 操作层级、悬停按压、选中状态、表单输入；后续包含开关、复选、单选与滑杆。 |
| 菜单、导航与定位         | 展开导航、浮动工具、分组入口与位置选择。                                 |
| 卡片、悬浮预览与人物展示 | 内容摘要、辅助资料、人物关系及场景化卡片；规模增长后可分这些二级组。     |
| 展开、切换与布局变化     | 折叠问答、页签内容、尺寸变化；后续包含弹窗、抽屉和面板。                 |
| 文字、图形与内容动效     | 分行、替换、描画与文本更新；按内容表现归类，再标注滚动或状态触发。       |
| 滚动与连续叙事           | 随滚动揭示、聚焦、停留、离开和段落编排。                                 |
| 图片、画廊与循环展示     | 图片揭示、视觉对照、连续图片墙和循环节奏。                               |
| 加载、进度与状态反馈     | 等待、分步执行、成功、跳过、失败和恢复。                                 |
| 页面转场                 | 遮挡切换、淡化、分块、方向与节奏；数量增长后按机制细分。                 |
| 主题切换                 | 明暗状态、触发原点、覆盖方向与整页一致性。                               |

一件案例只设一个主要归属，其他维度用标签交叉查找。例如折叠问答归“展开、切换与布局变化”，同时标注点击、键盘、高度变化和信息阅读；文字分行飞入归文字表现，标注滚动驱动，不再复制一份到滚动分类。随着内容增长，边界以主要教学目标判断，仍混淆时再调整名称。

建议保留的查找维度是：**用在哪里**（按钮、导航、卡片等）、**怎么触发**（点击、悬停、滚动、输入或状态变化）、**学习什么**（时序、空间、选择、信息层级等）、**适合什么页面**（作品集、内容站、工具页等）。来源与难度作为补充；初始不把所有标签同时摆给用户。具体界面与数据结构另行确定。

## 二、首轮候选取舍

以下依据当前仓库48件Great UI案例的正文、目录和已记录的原作行为整理，属于编辑判断；本清单没有进行新一轮浏览器验收，也不把原作当作开箱即可交付的完整组件。

- **主讲**：优先打磨的代表案例，能支撑一个清楚的教学目标；仍需完成精品内容审阅后才进入新合集的核心路线。
- **对照**：有望解释另一种选择的候选变体，围绕差异组织；没有新增判断价值就不收录。正式公开时质量门槛与主讲相同。
- **暂缓**：本轮不优先编入新版路线，写明理由。保留来源与已有成果，不自动删除当前网站内容；出现新的教学价值时可以重新选择。

本稿提议16件主讲候选、20件对照候选、12件暂缓；这是当前材料的取舍结果，不是配额、上线数量或合集容量限制。每个分类以后都可以继续增加通过相同标准的精品。原作缺陷只用于交代改造边界，不能单独作为“值得收录”的理由。

## 三、先补哪些教学缺口

现有48件素材偏重展示、悬停和转场。下一轮优先补“选择输入”“内容切换”“弹窗与抽屉”“拖拽与排序”等缺口，再比较其他来源是否提供更好的代表作。目录中的缺口不承诺已有案例，也不为凑齐分类强行收录。

[现有beUI文章](../../src/content/works/beui-motion-lab/zh.mdx)已包含十种真实组件演示，可先用作选材起点；它们尚未因本清单而变成新的独立案例。

| 可复用的候选            | 补充目标                                          | 初步取舍                                       |
| ----------------------- | ------------------------------------------------- | ---------------------------------------------- |
| Tabs                    | 选中标记移动、内容切换与位置稳定；区别于关闭/展开 | 优先补“展开、切换与布局变化”                   |
| Switch、Checkbox、Radio | 区分立即开关、多选和单选，并观察选中反馈          | 优先补选择输入；可先组织一组有真实任务的比较   |
| Range                   | 连续输入、刻度与反馈；键盘、触屏和数值精度        | 优先补选择输入                                 |
| Tilt                    | 倾斜如何提示空间和反馈鼠标位置                    | 与头像、资料卡的已有倾斜比较，只有新增价值才选 |
| Button、Accordion       | 比较不同来源怎样处理同一功能                      | 优先补强现有案例，不按库名复制课程             |
| Badge、Marquee          | 状态标识、循环与暂停                              | 分别与状态反馈、图片墙比较后再定               |

Rare UI与其他来源同样按缺口选材；此稿不根据库的名气预先承诺具体条目。来源、固定版本、许可和真实表现需在选定候选时核对；不先批量录制再为已有素材寻找教学理由。

## 四、第一次学，先走这条路线

建议先试八站短路线，每站只增加一个主要判断；完整分类库继续开放查找。下面是学习编排提案，不要求用户先读完所有案例才能开始做项目。

| 顺序 | 案例                 | 用户与Agent完成什么                                                 |
| ---- | -------------------- | ------------------------------------------------------------------- |
| 1    | 有层级的基础按钮     | 用真实操作分清主次、加载和禁用；让Agent展示状态，用户判断是否清楚   |
| 2    | 有分隔线反馈的图片卡 | 为自己的内容补合适的轻反馈，说明点击去向和长标题要求                |
| 3    | 折叠问答             | 比较单项/多项展开，调节展开节奏，用自己的长答案判断阅读是否顺畅     |
| 4    | 展开成面板的浮动导航 | 组织真实链接，让Agent处理手机、键盘和开关；观察动态是否帮助理解层级 |
| 5    | 分步状态清单         | 分清演示与真实执行结果，写清失败与恢复；观察状态是否可信            |
| 6    | 滚动文字揭示         | 用自己的短文案比较有无动效，判断阅读收益与滚动成本                  |
| 7    | 错峰页面转场         | 说明遮挡、内容就绪与揭开的顺序，观察连续导航是否拖慢任务            |
| 8    | 从一点展开的主题     | 把主题切换接到已有全站风格，观察触发位置与最终样式是否一致          |

“学习网页动效”不意味着一个页面应该叠加以上所有效果。串联练习可从作品集或小工具中选择一个真实目标，只取有帮助的少量案例，说明为什么其他效果不需要。进阶读者可直接查分类或从对照案例进入。

## 五、每件案例怎样同时教动效、组件和Agent协作

默认围绕**一个主要问题**展开：看参考与静态/变化状态 → 解释值得保留的设计决定 → 判断适用边界 → 给Agent自己的内容、目标和约束 → 对照真实结果修改。动效与组件行为相关时一起讲；不为每一例凑齐相同长度的栏目。

以折叠问答为例：既讲高度与透明度怎样一起变化，也讲为什么一次只开一项、需要比较答案时为何改成多项。用户向Agent说明自己的阅读任务与长答案，检查实际展开、键盘操作和手机阅读；不要求用户阅读状态变量或亲自修改源码。

共享原理与术语集中引用，每件案例保留自己的关键取舍和证据。改造练习只在能产生新判断时设置，串联任务在路线层组织；避免给数百个案例机械各写一套“拆解、改造、串联”。

进入公开精选前，编辑确认：效果与讲述有真实依据；值得借鉴的设计有明确理由；换成真实内容后仍有可迁移价值；与已有案例相比新增了值得学习的决定；说明来源、边界和必要改造；Agent协作步骤能产出可观察的结果。质量不达标就继续改或不收录，不以已录屏、已接入或目录缺项代替选择。

传播标题可以突出一个真实、可展示的结果，例如“让Agent把菜单从能打开，做到手机上也顺手”；标题里的收益必须在案例中实际呈现。合集本身保持《Vibe Coding 网页动效与交互》这个清楚、稳定的名字。
