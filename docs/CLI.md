# 项目命令说明

这些命令像项目的几个固定按钮。在项目文件夹打开终端，复制一条命令并按回车即可。

## 第一次准备

需要 Node.js 22.20 或更新的兼容版本。首次拿到项目或依赖清单变化后，运行 `npm ci` 安装锁定的工具版本。端到端测试另外需要已安装并完成首次设置的 **ego lite**，终端必须能调用 `ego-browser`；它不是 npm 依赖，也不会自动改用其他浏览器。

```bash
cd /Users/jachi/Desktop/Vibes
npm ci
```

## 常用命令

| 命令                 | 它会做什么                                                                                                          | 什么时候用                                                             |
| -------------------- | ------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------- |
| `npm run dev`        | 启动本地网站，终端打印访问地址，通常是 `http://127.0.0.1:4321/`；修改文件后自动更新页面。                           | 边修改边看效果。以终端实际打印的地址为准。                             |
| `npm run check`      | 依次检查类型、代码规则、排版格式和单元测试；任何一项失败就停止，整体返回失败。                                      | 每次修改完成后都运行。它不启动浏览器，不清空数据库。                   |
| `npm run test:e2e`   | 先构建网站，再启动 Cloudflare 本地服务，使用 ego-browser 模拟点击、输入、刷新、返回和手机阅读；结束后关闭测试服务。 | 检查真人使用的主要流程。运行前关闭占用 4322 端口的预览服务。           |
| `npm run db:reset`   | 清空**本项目本机测试库**，重新应用所有结构变更，再填入两条固定测试记录。                                            | 想恢复一份干净的测试环境。原有本地测试数据会被删除，先关闭预览再运行。 |
| `npm run db:migrate` | 只把尚未应用的结构变更加入本机数据库，不主动清空已有数据，也不填测试数据。                                          | 新增或修改数据库结构后。已经应用的迁移不会重复运行。                   |
| `npm run preview`    | 先构建，再用 Cloudflare Wrangler 在本机模拟线上运行环境，地址为 `http://127.0.0.1:4322/`。                          | 检查打包后的效果。改源码后需要停止并重新运行。                         |
| `npm run deploy`     | 构建网站，然后按 `wrangler.jsonc` 部署到已登录的 Cloudflare 账号。                                                  | 确认要上线并完成验收后使用；这会修改真实线上 Worker。                  |
| `npm run verify`     | 严格依次运行 `check` → `db:reset` → `test:e2e`；中途失败就停止。                                                    | 交付前的一次完整本地验收；它会清空本地测试库，但不会部署。             |

在普通终端中，`dev` 和 `preview` 会持续运行，按 **Ctrl+C** 停止。Astro 在 AI 环境中可能自动后台运行 `dev`，此时运行 `npx astro dev stop` 停止本项目开发服务。其他命令结束后会回到可以输入下一条命令的状态。

## 检查失败怎么办

看到红字或失败提示，先不要部署。把完整错误消息交给 AI 修复，再重新运行同一条命令；不能跳过出错的步骤。

- 类型检查：检查代码有没有把数字、文字或对象等用错。
- lint：检查容易出错的写法和代码规则，包括 JavaScript、TypeScript、Astro 文件不超过 300 行。
- 格式检查：检查缩进、换行和引号是否统一，只报告问题，不自动修改。
- 单元测试：用小案例检查内容完整性、数据库结构和本地命令的参数保护。
- 端到端测试：在真实 ego-browser 中检查分类、搜索、清空、刷新恢复、文章跳转、浏览器返回、手机宽度、禁用 JavaScript 阅读和不存在的页面。

需要修正格式时运行 `npm run format`，它会统一排版；随后再次运行 `npm run check`。其他子命令包括 `npm run check:types`、`npm run lint`、`npm run format:check`、`npm run test:unit`；`npm test` 等同于单元测试，`npm run build` 只构建网站。

## 本地数据库的边界

数据库结构文件放在 `db/migrations/`，固定测试数据放在 `db/seed.sql`。目前只有命令验收用的 `local_test_records` 表；网站内容仍来自 `src/data/works.json`，清空测试库不会清空网站卡片。这次没有增加用户、支付或其他业务表。

数据库与本地预览共用 `wrangler.local.jsonc` 和 `.wrangler/project-local/`。其中数据库标识只是本地模拟用标识，不是已创建的线上 D1 数据库。`db:reset` 只删除这份专用目录中的 D1 数据，保留项目其他本地运行数据；不接受额外参数，包括 `--remote`。

`db:migrate` 也固定为**本地**操作。以后需要线上数据库时，必须先明确真实数据库及迁移流程，不能把这些本地测试配置用于生产。迁移 SQL 本身仍可能删表或删列，编写迁移时必须检查内容；已经应用的迁移文件不要重写，应该新增下一个编号的文件。

## 浏览器和部署说明

测试需要本机 ego lite 可用，且需要操控本机浏览器。浏览器缺失、端口被占用、服务启动超时或页面断言失败，都会让 `test:e2e` 和 `verify` 返回失败。单独运行 `test:e2e` 不会重置数据库；完整验收请用 `verify`。

Playwright 测试是 GitHub CI 的浏览器验收实现；本地 `test:e2e` 使用 ego-browser。GitHub 云端按已确认的方案运行相同的 `npm run verify`，其中浏览器步骤使用 Playwright；本地仍使用 ego-browser。两种环境明确报告各自使用的浏览器，不把云端结果称为 ego-browser 验收。

`deploy` 沿用项目已有的直接 Wrangler 部署，目标 Worker 名称是 `vibes-explore`；需要你自己的 Cloudflare 登录和权限。仓库另有 `.openai/hosting.json` 指向现有 Sites 托管站点，直接 Wrangler 部署**不等于更新该 Sites 地址**。本次仅配置并验证部署打包，不登录、不部署、不迁移线上数据库。

类型检查覆盖网站及命令脚本；格式检查覆盖源码、项目文档和受支持的配置文件，跳过依赖、构建产物、本地状态、研究资料、托管元数据和原始公开资源。Shell 脚本由 `bash -n` 检查语法，SQL 由单元测试实际执行验证。

## 文件体积预算

`npm run budget` 先构建，再检查浏览器脚本和首页的压缩大小，防止网站无意中变得很重；超过上限或缺少构建产物就失败。具体阈值见 [常量说明](CONSTANTS.md)，PR 上会单独显示 `budget` 检查。
